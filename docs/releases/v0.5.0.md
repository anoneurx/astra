# Astra 0.5.0

**Phase 4 milestone: memory engine v1 with audited lifecycle, short/long-term
session split, inference wiring, Rust vector core, and retrieval-quality
thresholds adopted.** Astra can now remember facts across turns, retrieve
them at inference, and prove — via an honest negative-control measurement on
the toy model — that the retrieval channel is functional end-to-end. The full
RAG-vs-baseline *generation benefit* is tracked to the Astra-5M model
(`docs/PLAN-ASTRA-5M.md`).

## Highlights

- **Memory engine v1** (`python/astra/memory/`, 31 engine/session tests):
  immutable records (`kind`/`source`/`confidence`/`verification_status`/tags/
  attribution), JSON store with atomic writes + append-only JSONL audit, lazy
  (re-)embedding, lifecycle (`correct` immutable revision, `soft_delete` with
  audited purge, `expire` TTL sweep, `mark_disputed`/`resolve` conflict queue).
  Flat exact cosine retrieval + hybrid ranking (cosine-led defaults adopted
  from the GAP-5 ranking study; heavy recency penalised). Working-context
  injection builds `<|memory|>` blocks with token-budget + attribution.

- **Inference wiring (G1)**: `service/inference.py --memory <store>` opens
  a store, recalls memories per prompt, prepends the `<|memory|>` block, and
  returns `memory.included/dropped/block_tokens` in the response; opt-out via
  `"memory": false` per request. `inference/generate.py` recalls per turn in
  the terminal chat, printing which records were used.

- **Short/long-term session split (G3)**: `SessionMemory` (`session.py`)
  writes TTL'd `kind="session"` records scoped to a session id; isolated from
  durable recall by default (`store.search` excludes session kinds);
  `close()` bulk soft-deletes; `promote(session, rid, kind)` copies a session
  record into a durable record with attribution. CLI: `remember`,
  `session-recall`, `session-close`, `promote`.

- **Rust vector core (G4)**: `astra-rt` restructured into a lib crate
  (`memory.rs` flat exact cosine + base64-f32 store decode; `sha256.rs` split
  out) plus the `astramem` CLI. `tools/rust_mem_crosscheck.py` asserts top-1
  exact + top-k set parity with the Python reference on identical embeddings.
  `make rust-mem`. HNSW/ANN remains a later milestone.

- **Eval set + ranking study (G2, G5)**: `datasets/memory/qa_v1.json`
  (10 facts, 11 items, leak-free, `eval-quarantine` by policy);
  `tools/memory_qa.py` measures RAG vs baseline (fact-recall, gold-retrieval
  rate, conditioning probe); `tools/memory_ranking_study.py` sweeps weight
  grids to select defaults; `benchmarks/suites/core-retrieval.json` v2
  carries adopted thresholds (hit@1 ≥ 0.8, hit@5 = 1.0, MRR ≥ 0.9,
  nDCG@5 ≥ 0.9) enforced by `tools/memory_eval.py --enforce` on the
  HashEmbedder baseline.

## Known limitations / still in development

- **Astra-5M parked**: the toy model is a documented *negative control* for
  RAG generation (free-form recall 0.0; conditioning probe −0.38 nats);
  retrieval quality proves the channel works; the *generation benefit* is
  tracked to `docs/PLAN-ASTRA-5M.md`.
- **HNSW/ANN** deferred to a later milestone.
- **LiteLMExtractor on toy encoder** is a non-gated baseline (hit@1 0.27 /
  MRR 0.50); re-measure with the real encoder.
- **Session records** currently share the long-term store file (separated by
  kind); a physically-partitioned session store is a future optimisation.

## Upgrade from 0.4.0

This is a backwards-compatible feature addition. The new memory engine,
session split, Rust memory CLI, and ranking study are additive. The inference
service gains optional `--memory ...` flags; existing deployments that omit
the flag behave identically to 0.4.0.
