# Astra 0.2.0

**Training Foundation** — the Phase-2 hardening release: config-driven,
reproducible, audited, and experiment-tracked training on top of Astra 0.1.0.

## Highlights

- **Optimizer/scheduler registry** — `OPTIMIZER_REGISTRY` (`adamw`) and
  `SCHEDULE_REGISTRY` (`cosine`) with `build_optimizer`/`build_schedule`
  (`python/astra/training/optim.py`). Configs select them via `optimizer` /
  `scheduler` keys; extending the loop no longer requires editing it.
- **Gradient accumulation** — `accum_steps` in `python/astra/training/loop.py`
  accumulates gradients across micro-batches, averages them, then clips and
  steps. `accum_steps=1` is bit-identical to the Astra 0.1.0 loop; equivalence
  to a single large batch is proven by test, and `accum_steps=3` runs are
  bit-identical across repeated runs.
- **Experiment tracking** — `ExperimentStore`
  (`python/astra/experiments/store.py`) logs one JSON file per run with
  seed, git commit, environment, config, loss/val history, and final metrics;
  queryable via `tools/experiments.py` (`list`, `show <run_id>`,
  `query field=value` with `__gt/__lt/__ge/__le` filters). Every `train()` call
  auto-logs its run.
- **Audited run manifests** — each run records `git_commit` + full
  `environment` (python, numpy, machine, cpu, threads) in `report.json` and
  checkpoint manifests, so every checkpoint is tied to its exact code + env.
- **Per-shard validation loss** — `val_shards` reports loss/perplexity broken
  into contiguous shards (`loss_by_shard`), per docs/TRAINING.md § 2.8.

## Exit criteria (docs/ROADMAP.md Phase 2)

| Criterion | Result |
|---|---|
| Reproduction test (same-seed determinism) | PASS — bit-identical loss trajectory |
| Scheduler tests | PASS — boundaries, clamping, monotone post-warmup decay |
| Accumulation equivalence tests | PASS — N micro-batches ÷ N == one macro batch |
| Two identical configs reproduce | Verified at `accum_steps` 1 and 3 |
| Experiment store queryable | PASS — `tools/experiments.py query` |

## Verification

- **Tests: 42/42 pass** (`make test`, OPENBLAS 8 threads).
- **Birth test: all PASS** — val_loss 3.9158, unchanged from Astra 0.1.0
  (`tools/birth_test.py`, "ASTRA 0.1 STATUS: BORN").
- Reproducibility: bit-identical `loss_hist` + final val across repeated runs
  at `accum_steps=1` and `accum_steps=3`.

## Known limitations / deferred

- **Learning-rate sweeps** — driver tooling not yet built; the experiment store
  already supports the queries a sweep needs.
- **Mixed precision** — NumPy float32 reference only; bf16/fp16 planned
  (docs/TRAINING.md § 4).
- **Distributed training** — out of scope by policy until Phases 2+ hooks
  (docs/HARDWARE.md).
- **Best-validation-loss checkpointing** (TRAINING.md § 2.9) — interval
  checkpoints only today.

## Changes since 0.1.0

- 0.1.0 → 0.2.0: optimizer/scheduler registry, gradient accumulation, experiment
  tracking + CLI, run-manifest audit fields (git + environment), per-shard loss,
  and the Phase-2 exit test suite. See `docs/CHANGELOG.md`.

## Reproducibility

- Training artifacts remain deterministic; manifests now additionally record
  `git_commit` and `environment` at write time.
- Same seed + same config + same data ⇒ bit-identical loss trajectory.
