# Astra 0.4.0

**Phase-3 tail closure: model registry v1, inference service skeleton
(Python + Rust), ACTIVE(thresholded) benchmark suites, and the gate for
registered artifacts.** This is the incremental release that converts the
Phase-3 components into a productized, auditable service path (`docs/ROADMAP.md`
Phase 3 deferred items). The full-size core model remains parked per
`docs/PLAN-ASTRA-5M.md`.

## Highlights

- **Model registry v1** (`python/astra/registry.py`, `tools/registry.py`) —
  immutable, append-only JSON registry of registered artifacts. Each entry
  (docs/VERSIONING.md § 5): `semver`, `commit`, `config_id` (content-addressed
  from the config file), `data_manifest_id`, `checklist_id`, `eval_report_id`,
  `sha256`, plus `params`, `step`, `size_bytes`, `created_at`. Register is an
  **audit action**: re-registering an existing sha with different metadata is
  refused unless `--force`; the registry also provides `verify`, `show`,
  `list`, and round-trip JSON persistence.
- **Inference service skeleton** — the Phase-3 Python+Rust service path is
  started:
  - Python reference service (`service/inference.py`): stdlib
    `ThreadingHTTPServer` wrapper over the KV-cache decoder. Endpoints
    `GET /health`, `POST /generate` (prompt, max_new, temperature, top_k,
    top_p, window, seed). Stateless per request (fresh cache per turn).
  - Rust runtime skeleton (`service/rust`, crate `astra-rt` v0.4.0):
    dependency-free SHA-256 (FIPS 180-4) checkpoint fingerprinting + CLI that
    verifies a `.npz` against an expected sha256 and exits nonzero on mismatch.
    Cross-validated against the Python sha (both `dd9432cc…310` for
    `checkpoints/name/resumed/final.npz`). The Rust *engine* (forward/backward
    math) remains a deferred milestone.
- **ACTIVE(thresholded) benchmark suites** — `core-basic` promoted from
  ADVISORY to **ACTIVE** (manifest v2) with thresholds recorded under
  `threshold_decision`; adopted 2026-09-08. The gate now passes only when all
  ACTIVE suites pass; ADVISORY suites are reported but cannot promote.

## Known limitations / deferred

- **Full-size core model (Astra-5M+) — parked.** `docs/PLAN-ASTRA-5M.md`
  defines the training plan; the toy checkpoint remains the only released
  artifact. `core-reason`+ suite thresholds still to be assembled for it.
- **Rust inference engine** — the `astra-rt` crate is a fingerprint-verification
  skeleton, not a forward-pass runtime. Python reference remains the engine;
  Python↔Rust inference-equivalence gate deferred with it.
- **Registry storage** — flat JSON file under `checkpoints/` (git-ignored);
  SQLite/relational store is a later milestone (docs/ARCHITECTURE.md registry
  row). Learned-positions + context beyond `max_seq_len` still out of bounds
  (from 0.3.0).
