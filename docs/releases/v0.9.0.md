# Astra 0.9.0

**Phase 6 milestone: automated promotion gate, registry promotion/rollback,
append-only audit, and a supervised continuous-improvement worker.** The
candidate → evaluate → accept/reject → deploy loop now runs under a
deterministic gate engine with a full audit trail and an offline rollback
drill; a supervised continuous-improvement demonstration promotes a candidate
that improves a held-out target while preserving prior capability
(docs/PHASE_STATUS.md, docs/LEARNING.md § 1.11–1.13).

## Highlights

- **Gate engine v2** (`python/astra/learning/gates.py`): `GateEngine` runs the
  promotion decision from base-vs-candidate deltas under versioned rules —
  `gain` (target must improve ≥ `min_gain`), `no_regress` (other partitions
  must not drop more than `max_regress`), `absolute` (core-suite thresholds) —
  with an `auto`/`manual` (human-approval) policy. Accept/reject is
  deterministic. 8 gate tests.

- **Registry promotion + rollback** (`python/astra/registry.py`): the
  append-only immutable registry gains an active-sha pointer per name;
  `promote` points active at a registered candidate (previous entry retained
  for rollback), `rollback` restores the previous registered entry, `history`
  enumerates the lineage. 4 registry tests.

- **Append-only audit** (`python/astra/learning/audit.py`): every
  promote / reject / rollback / approve is an immutable JSONL row
  (`learning/audit.jsonl`) carrying the gate decision verbatim + git commit —
  the single source of truth for what happened. 2 audit tests.

- **Shared measurement** (`python/astra/learning/evaluate.py`): deterministic
  `corpus_loss` / `load_model` / `partition_metrics` base-vs-candidate CE,
  reused by the Phase-5 loop driver and the Phase-6 worker.

- **Supervised worker** (`tools/self_improve.py`): one command runs
  intake → candidate train → measure → gate → promote/reject → audit; the
  `--rollback-drill` mode exercises automatic rollback offline (promote a
  regressing artifact, restore the prior active sha, assert + audit).

- **Reproducible demonstration**: 10 validated experiences teach the toy
  `name` checkpoint a new fact. Candidate improves the held-out target
  **−0.775 CE** (base 5.155 → candidate 4.380) with regression **+0.009 CE**
  (Astra capability preserved) → ACCEPT → promoted `astra-name` 0.9.0 in the
  registry. Rollback drill: promoted a regressing artifact then restored the
  prior active sha; audit trail records both the promote and the rollback.

## Known limitations / still in development

- **Supervised, not autonomous**: `tools/self_improve.py` requires an explicit
  invocation; a scheduled/automated worker that self-promotes is Phase 7.
- **Alerting** is console + audit only; out-of-band notification deferred.
- **Drift detection** (distribution-drift watch) is Phase 8.
- **Preference (ranking) training path** remains on the Phase-5/6 backlog
  (schema exists; trainer uses the `good` pair for LM-style learning).
- **Toy-model scale**: the demonstration is on the tiny `name` checkpoint;
  scaling the loop to Astra-5M is tracked in `docs/PLAN-ASTRA-5M.md`.

## Upgrade from 0.7.0

Backwards-compatible feature addition. The gate engine, registry promotion,
audit log, and self-improve worker are additive; the Phase-5 loop driver
behaves identically (now backed by the shared `evaluate` module). The registry
file gains an `active` map — old registries load fine and default to the latest
entry for any name not yet promoted.
