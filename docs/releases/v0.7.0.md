# Astra 0.7.0

**Phase 5 milestone: learning engine v1 — feedback intake cascade with trust
tiers + quarantine, experience store with dedup/provenance, candidate trainer
with replay, and a reproducible end-to-end candidate-vs-active demonstration on
the toy model.** Astra can now convert validated human feedback into a
*separate candidate model* that measurably learns a new fact without forgetting
prior capability, with every improvement traceable to validated experiences
(docs/LEARNING.md, docs/ROADMAP.md § Phase 5).

## Highlights

- **Feedback intake + validation** (`python/astra/learning/feedback.py`):
  `make_feedback` + `validate_feedback` run the intake cascade —
  source/authenticity → trust-tier policy → plausibility → per-tier confidence
  → dedup. Any failure quarantines the record with a reason (never trained).
  Trust tiers and per-tier minimum training confidence live in
  `python/astra/learning/__init__.py` (`TRUST_TIERS`).

- **Experience store** (`python/astra/learning/experience.py`): append-only
  JSONL store at `learning/store/store.jsonl` (git-ignored). Training examples
  carry kind (`sft` / `preference` / `fact`), status (`active` / `quarantined`
  / `withdrawn`), and provenance (`feedback_id` back to the source feedback).
  Deterministic content dedup makes re-submission a no-op (no training-weight
  inflation).

- **Candidate trainer** (`python/astra/learning/candidate.py`): `train_candidate`
  loads the **active checkpoint** and fine-tunes a *separate candidate* on
  validated SFT experiences tokenized to the pretraining BPE, interleaving the
  original corpus as a replay stream (`replay_ratio`) to prevent catastrophic
  forgetting. The candidate artifact ships a provenance manifest (base sha256,
  experience ids, replay tokens, seed, git commit). Deterministic per (seed,
  config, experiences, replay).

- **Eval driver** (`tools/learning_loop.py`): one command runs the full loop —
  intake → store → candidate → base-vs-candidate mean-CE on a **held-out target
  partition** (loss reduction ⇒ generalization, not memorization) and a
  **regression partition** slices the original pretraining data (rising loss ⇒
  forgetting); provisional accept/reject. `tools/learning_eval.py` is the
  substring-hit cross-check on a versioned JSON eval set.

- **Reproducible demo**: 10 validated `human_verification`-tier experiences
  teach the toy `name` checkpoint a new fact — "Astra is from Nova". The
  candidate improves the **held-out** Nova partition by **−0.775 CE**
  (base 5.155 → candidate 4.380) and the Astra regression partition by
  **+0.009 CE** (no forgetting); decision ACCEPT. The exact numbers reproduce
  run-to-run (deterministic loop).

## Known limitations / still in development

- **Preference (ranking) training path**: schema exists (`preference` kind);
  the trainer currently uses only the `good` pair for LM-style learning.
- **Automated promotion gate** (registry promotion + audit + rollback) is
  Phase 6; this release gives a *provisional* accept/reject decision.
- **Feedback-confidence reward-weight research** and threshold curves remain
  open research.
- **Live leak coverage**: `learning/store` is git-ignored like `memory/store`;
  the demo runs its own held-out-leak gate before training.
- **Toy-model scale**: the demonstration is on the tiny `name` checkpoint;
  scaling the loop to Astra-5M is tracked in `docs/PLAN-ASTRA-5M.md`.

## Upgrade from 0.5.0

Backwards-compatible feature addition. The learning engine and tools are
additive; memory, inference, and training behave identically to 0.5.0.
